# SillyTavern 历代人生管理器

面向“死亡后换入同一世界另一具真实身体”的长篇 SillyTavern/MVU 玩法。插件负责保存并向 AI 注入完整当前身体档案、按世代显示已经结束的人生摘要，并把上一世归档草稿安全写入同一本现有世界书。

## 0.5.0 智能注入与当前人格执行

- 默认改为“智能注入”：换身后首轮发送完整人物卡，日常回合只发送核心身份、每轮必需的人格/思维资料、完整状态描述、正文身体变化和限长的历代经历索引。
- 当前身体的性格、价值观、喜恶、愿望恐惧、情绪习惯、认知边界、知识语言及技能经验会在每次生成前单独提取，MVU 中的后续成长覆盖接管时静态人物卡。
- 新增行动—人格协调规则：玩家决定“做什么”，当前身体决定“如何理解和执行”；胆小角色仍能执行玩家选择的勇敢行动，但会呈现符合设定的风险判断、紧张或谨慎方式，不能以性格为由否决行动。
- 设置页显示本轮实际注入模式、字符数和估算 Token，便于确认上下文占用。

## 0.4.0 正文实时身体追踪

- 当 MVU 在最新回复中尚未把变量更新写回楼层快照时，插件会从该回复的 `<JSONPatch>` 安全补全当前显示与 AI 注入。
- 兼容预设使用的 `/最新动态/*` 路径别名，自动对应到实际的 `/主角/*` 数据；例如“小腿割伤”和 HP 变化会立即出现。
- “当前身体”页增加“正文实时身体状态”，展示状态效果详情，并跟踪伤病、外貌、身体、变异、改造、形态、器官、义体、植入、血脉、特征与穿着变化。
- 实时生命值和状态效果优先于接管时人物卡中的静态“健康”文本，避免受伤后仍显示“无状态效果”。
- 变量补全只生成内存中的实时视图，不擅自改写聊天、MVU 原数据或人物卡。

## 0.3.0 界面更新

- 采用深色星轨、紫金高光的全新视觉风格。
- 当前身体增加人物主视觉、身份标签和生命值进度条。
- 历代人生改为时间线卡片，设置项改为分区面板。
- 针对酒馆侧栏和手机窄屏进行响应式适配，不改变现有数据与同步逻辑。

## 主要功能

- 顶部显示当前身体概览；下方按人物卡原有板块展示全部资料，并永久保留完整原始人物卡文本。
- 在正文人物卡下提供“导入为当前身体”和“确认换身并导入”按钮；设置页也可从历史正文选择人物卡。
- 自动识别正文中“人物卡 → 玩家确认换身”的完整确认链，并兼容预设曾生成的“发送‘确认换身’，正式接管……”说明型选项。
- 聊天内建立独立的当前身体与历代人生档案，不再以 MVU 新字段是否成功写入作为唯一依据。
- 支持“扫描并修复本聊天”，可从已有确认链恢复当前身体和人物卡中携带的历代摘要。
- 默认在每轮生成前智能注入当前身体；可切换为每轮完整注入、始终精简注入或关闭。
- 正文中的伤势、状态、变异和身体改造会同步到当前身体页与下一轮 AI 注入；MVU 快照延迟时会从最新正文变量补丁补全。
- 消息到达后分阶段重读 MVU，避免插件在变量尚未写完时读取旧值。
- 删除、编辑、切换或重新生成楼层后自动与当前正文对账；人物卡或确认来源消失时，撤销孤立身体、相关本地历代记录和 AI 注入。
- 设置页提供“从当前正文重新同步”和“清空本聊天插件记录”；清空后不会立刻把旧确认楼层重新导入，新产生的确认记录仍可识别。
- 支持“万相欲身 · 形态记录 v2”HTML 人物卡；即使 MVU 没有及时替换姓名、年龄、性别、身份和职业，也能显示已经确认的新身体。
- 兼容尚未建立 `主角.载体档案` 的旧聊天：从旧版主角字段、世界地点、生命值和状态效果显示现有资料，不修改原变量。
- 旧聊天会按开局姓名匹配历史回复中的 `<char_info>` 主角人物卡，用它补齐姓名、年龄、性别、种族、身份与职业；不会把其他 NPC 的人物卡误作主角，也不会回写 MVU 变量。
- “历代人生”只显示真正的人生摘要：优先读取 `历代记忆摘要` 与已确认人物卡中的历代经历，并排除世界书协议、模板、测试示例和确认提示词。
- 兼容人物卡中“历代经历记忆”标题无冒号、`第N世·姓名：经历` 等格式；即使 MVU 未保存新增的历代字段，也会直接从确认后的正文变量更新中恢复上一世摘要。
- 手动导入的当前身体不再覆盖自动恢复出的历代人生；删除临时候选楼层时，只撤销候选和依赖它的当前身体，不误删仍由现存确认卡或正文变量更新证明的已结束人生。
- 不替玩家选择候选或自动发送确认口令；手动导入仅在玩家点击后执行。
- 把 `待归档人生词条` 追加到所选的现有世界书，不创建第二本世界书。
- 相同词条自动去重；同名异文立即停止，不覆盖旧记录。
- 世界书保存并从后端回读成功后，才把状态改为“已写入世界书”并清空临时草稿。
- 对新旧身体完全相同的人格、感情、知识语言、技能和属性显示继承警告，不擅自修改。
- 导出当前身体、历代人生词条和完整聊天原文备份。

## 使用流程

1. 当前身体真正死亡后，直接在正文中让 AI 生成或修改下一具身体的人物卡。
2. 由你亲自在聊天中发送口令“确认换身”，或点击人物卡下方的“确认换身并导入”。
3. 插件自动把这张已确认卡保存为当前身体，并把其中的前世简要经历显示在“历代人生”。自动识别失败时可在设置页手动导入或扫描修复。
4. 若预设生成了 `待归档人生词条`，可在“历代人生”页将其写入当前世界书。

## 数据与安全边界

- 插件不修改角色卡、预设或无关世界书词条。
- 等级、属性、资源、地点与状态仍以最新 `stat_data.主角` 为事实来源；身份资料优先采用最后一次已经确认换身的人物卡，旧聊天则从匹配到的初始主角人物卡中只读补全。
- 插件只读取确认链，不会把人物卡写回 MVU，也不会把尚未确认的人物卡当成当前身体。
- 完整聊天原文只进入你主动下载的备份，不注入模型。
- 普通 AI 回复不能直接新增世界书词条；只有本插件的明确按钮操作会写入。
- 建议换身前先导出备份。

## 兼容性

需要当前 SillyTavern 的 `SillyTavern.getContext()` 公共接口。读取和写入 MVU 时优先使用酒馆助手提供给扩展的 `TavernHelper.getVariables/updateVariablesWith`，其次使用 `Mvu.getMvuData/replaceMvuData`，并为旧版接口及常见消息变量结构保留兼容回退。
