# SillyTavern 历代人生管理器

面向“死亡后换入同一世界另一具真实身体”的长篇 SillyTavern/MVU 玩法。插件负责识别当前身体、按世代显示已经结束的人生摘要，并把预设生成的上一世归档草稿安全写入同一本现有世界书。

## 安装

在 SillyTavern 中打开：

`扩展 → 安装扩展`

粘贴仓库地址：

`https://github.com/jiangshuyu132-cloud/SillyTavern-LegacyLifeManager`

“分支或标签名”留空，选择“只给我安装”即可。

## 主要功能

- 查看 `stat_data.主角` 的当前身体、身份、属性、技能和状态。
- 自动识别正文中“人物卡 → 玩家精确发送确认换身”的完整确认链；最后一次已经确认的人物卡就是当前身体，后面尚未确认的新候选不会生效。
- 支持“万相欲身 · 形态记录 v2”HTML 人物卡；即使 MVU 没有及时替换姓名、年龄、性别、身份和职业，也能显示已经确认的新身体。
- 兼容尚未建立 `主角.载体档案` 的旧聊天：从旧版主角字段、世界地点、生命值和状态效果显示现有资料，不修改原变量。
- 旧聊天会按开局姓名匹配历史回复中的 `<char_info>` 主角人物卡，用它补齐姓名、年龄、性别、种族、身份与职业；不会把其他 NPC 的人物卡误作主角，也不会回写 MVU 变量。
- “历代人生”只显示真正的人生摘要：优先读取 `历代记忆摘要` 与已确认人物卡中的历代经历，并排除世界书协议、模板、测试示例和确认提示词。
- 不再提供“换身候选”页面，也不导入人物卡或替玩家填写确认口令；候选生成、修改和确认完全留在正文中完成。
- 把 `待归档人生词条` 追加到所选的现有世界书，不创建第二本世界书。
- 相同词条自动去重；同名异文立即停止，不覆盖旧记录。
- 世界书保存并从后端回读成功后，才把状态改为“已写入世界书”并清空临时草稿。
- 对新旧身体完全相同的人格、感情、知识语言、技能和属性显示继承警告，不擅自修改。
- 导出当前身体、历代人生词条和完整聊天原文备份。

## 使用流程

1. 当前身体真正死亡后，直接在正文中让 AI 生成或修改下一具身体的人物卡。
2. 由你亲自在聊天中发送精确口令“确认换身”。
3. 插件自动把这张已确认卡识别为当前身体，并把其中的前世简要经历显示在“历代人生”。
4. 若预设生成了 `待归档人生词条`，可在“历代人生”页将其写入当前世界书。

## 数据与安全边界

- 插件不修改角色卡、预设或无关世界书词条。
- 等级、属性、资源、地点与状态仍以最新 `stat_data.主角` 为事实来源；身份资料优先采用最后一次已经确认换身的人物卡，旧聊天则从匹配到的初始主角人物卡中只读补全。
- 插件只读取确认链，不会把人物卡写回 MVU，也不会把尚未确认的人物卡当成当前身体。
- 完整聊天原文只进入你主动下载的备份，不注入模型。
- 普通 AI 回复不能直接新增世界书词条；只有本插件的明确按钮操作会写入。
- 建议换身前先导出备份。

## 兼容性

需要当前 SillyTavern 的 `SillyTavern.getContext()` 公共接口。读取和写入 MVU 时优先使用酒馆助手提供给扩展的 `TavernHelper.getVariables/updateVariablesWith`，其次使用 `Mvu.getMvuData/replaceMvuData`，并为旧版接口及常见消息变量结构保留兼容回退。
