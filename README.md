# SillyTavern 历代人生管理器

当前版本：**0.11.1**。

## v0.11.1：动态主档补齐与正文证据校验修复

- 修复无 `gametxt` 标签的普通正文被 HTML 折叠标题抢占的问题；折叠标题不再被当作唯一正文。引用校验兼容加粗、全半角、引号及空白排版差异，但不会把改写句、否定句、不同数值或图片/推理内容当成真实依据。
- 字段独立校验：一项引用失败不再退回同批全部有效更新。已核对字段融入完整动态主档；未接收项显示具体板块、字段、失败引用与原文，可展开“查看待补齐来源与具体失败引用”。
- 待补齐来源及失败项形成持久队列，随备份保存；后续无关回复、空 `changes` 回执、总结隐藏不再清空旧问题。每轮分批携带完整来源（最多三条，通常不超过四万字符；单条超长原文仍完整保留），模型修正或显式返回 `reviewedSources` 后才移出队列。回执是模型的核对声明，不是语义正确性的绝对保证。
- 更新刷新后自动重新校验现有失败回复，排版误拒可直接恢复，不必再生成。真正缺少原文依据的项目仍保留旧有效值，不会为了消除警告硬写入。普通回复会携带具体原文、失败字段、复制引用的要求与来源编号。
- 同一份完整动态主档仍用于界面和下一轮扩展提示；固定原档不修改。没有额外付费模型调用，不要求重新导入世界书、预设或人物卡，也不要清空账本。
- 回归测试覆盖旧版误拒自动恢复、部分接收、空回执不误清、多条补齐队列、隐藏/备份恢复、编辑/删除被引用来源的撤销，以及真实提示写入路径。测试使用虚构角色，没有调用真实生成模型；离线测试通过不等于用户正在运行的酒馆已被远程更新。

## v0.11.0：固定原档＋完整动态主档

现在明确分为三层，不能用一串“状态效果”代替完整人物卡：

1. **接管时身体档案（固定原档）**：保留完整原文和全部板块，只供追溯，正文变化不改写它。
2. **当前有效身体档案（动态主档）**：以原档的全部板块与字段初始化；正文变化逐字段融入。化妆、卸妆、发型、声音、气味、卫生、衣物、身体结构、病程、认知、背景经历等都可维护；未改变的细节继续完整保留。界面与提示读取同一份材料化主档，不是只显示变化清单。
3. **当前有效动态覆盖**：保留最新 MVU 状态、数值与即时效果，物品、任务和关系等原有模块照常使用。

### 如何更新与核对

- 酒馆扩展管理中更新本扩展后刷新页面，确认 **0.11.1**。当前身体页往下可看到“动态主档”，其下是折叠的“固定原档”。无需重新导入人物卡，也不要清空账本。
- 正常剧情的每轮发送完整动态主档及维护协议；旧“智能/精简”选项也不再省略动态人物细节。“关闭注入”、场外讨论、换身候选及确认交接仍按原安全门控处理。
- 插件要求模型在正文后输出 `<LegacyBodyUpdate>` JSON：身体标识、板块、字段、新的完整字段描述、可核对的正文摘录。没有变化也应输出空变化回执。插件独立保存，不依赖旧 MVU schema 保留新增字段；不修改聊天正文、世界书或 MVU 身份事务。
- 有效变化立即写进对应动态板块；卸妆/移除使用明确的“无/已移除”值，不恢复固定原档的旧值。非法字段、跨身体更新、无正文依据、半截 JSON 不会作为成功更新。这里验证的是格式、身份和文字依据，不能机械证明模型的语义判断百分之百正确。
- **旧正文只有化妆等叙述、没有更新块时，不会凭空猜测并宣称已同步。** 插件显示“待核对”，把最近相关正文带入下一次普通回复要求补齐。模型正确提交后，动态板块显示新描述和来源楼层。漏写/错误会持续提示；可在下一条用户消息提醒“核对当前身体变化，并按插件维护协议补齐动态主档”。无明确发生的事实不得编造。
- 固定原档不再作为第二份当前设定重复注入。详细动态档案优先于简短状态条；最新数值和明确发生的治愈/移除仍有效，不能借旧病史复活已经失效的状态。

### 隐藏楼层、备份与生成保障

- 已接受的字段更新、来源记录与完整动态档保存在本聊天元数据中。总结、隐藏旧楼层、暂时拿不到快照不等于撤销变化。编辑/切换某条回复时重放其当前版本；明确删除时撤销本次可核对到的来源，未在运行时出现的历史备份不因一次空扫描全部清除。
- 原有完整备份包含固定原档、动态档案和更新记录。导入后仍经过身份核对，再将动态主档写入提示区。导入或提示写入失败会回滚账本与设置。删除聊天本身、清浏览器/服务器数据不是备份方案，请另外保存导出的文件。
- 使用 SillyTavern 的生成拦截接口：新用户消息进入聊天后、构建请求前，再次准备完整动态主档；提示接口失败或可读提示区内容不一致时暂停本次生成。普通刷新和生成事件继续作为兼容刷新入口。
- 面板的“已写入酒馆提示区”表示插件已投递，不等于模型服务已经收到或保证逐条遵守。可在插件设置查看完整投递内容，并在酒馆提示查看器检查实际请求；模型上下文上限、预设过滤、第三方接口仍可能影响最终请求。没有额外调用付费模型。
- 本版维护协议由插件每轮自行注入，**不要求替换现有世界书/预设**。如果预设另有严格输出过滤导致更新块被删，需保留此块，不能只更新界面。

接口依据：[SillyTavern 生成拦截器](https://github.com/SillyTavern/SillyTavern/blob/release/public/scripts/extensions.js)、[扩展提示接口与请求构建](https://github.com/SillyTavern/SillyTavern/blob/release/public/script.js)。

## v0.10.0：可验证的完整备份恢复与自由拖动入口

- “设置与备份”新增完整备份导出、导入。备份包含当前身体、历代人生、头像、跨世金钱回执、可信确认记录、插件设置、匹配的历代世界书词条及聊天原文，并带有完整性校验；截断或被修改的文件会拒绝导入。
- 导入前会展示来源、时间、当前身体和历代条目数量，并自动保存导入前恢复点。只有备份身份与当前正文至少两个稳定身份字段一致时，才允许替换当前身体；不一致的资料只安全保留，不冒充当前人物。
- 成功恢复后强制切换“严格主档案”，立即通过酒馆扩展提示接口投递完整人物卡、人生背景和当前动态，并核对实际构建的提示包含姓名与主档案权威标记；失败时插件数据和设置一起回滚，不会出现只有界面恢复、AI 没收到却仍提示成功的半成品状态。以后每次生成前仍会重新合并正文最新变量并再次投递。
- 正文紫色“历”浮悬球可用鼠标或触控自由拖动。位置按屏幕比例保存，刷新、重新打开或窗口尺寸变化后仍保留，并自动限制在可见区域内；轻点仍然打开面板。
- 实时 `stat_data` 暂时没有姓名时，只要种族、职业等至少两个稳定字段与已确认档案一致，插件仍继续向 AI 注入完整档案，不再仅因姓名字段被总结隐藏而停发。

## v0.9.5：运行时旧楼层缺失修复

- 修复导出的聊天文件里仍有完整人物卡，但酒馆当前页面把旧回复留在滑动版本、推理兼容字段或其他消息副本时，插件只读取 `mes` 而误判“没有人物卡”的问题；现在会读取所有已知消息变体并按人物卡指纹去重。
- 普通打开、刷新、生成前校验不再把“一次扫描暂时读不到旧楼层”当成删除证据。已经确认的当前身体不会因此自动清空；需要按当前正文彻底撤销时，仍可使用“从当前正文重新同步”进行明确重建。
- 如果 0.9.4 已经误清空当前身体，会从滚动安全备份或升级迁移备份中查找完整人物卡，并要求当前实时 MVU 至少两个稳定身份字段（姓名、种族、职业）一致且身体仍存活，才自动恢复；不会仅凭一项相似字段恢复错误身份。
- 热更新后的旧事件监听器会自动失效，跨模块通知共用去重记录，避免同一次校验产生两条相同提示。

## v0.9.4：旧聊天无凭据自愈

- 修复已经加载 0.9.3、但更早一次错误对账已把当前身体和永久可信键一起清空时，界面仍停留在“当前变量未提供姓名”的问题。
- 当历史楼层快照和插件可信键都缺失时，新增受限兜底：必须同时存在完整人物卡、玩家独立发送的精确口令 `确认换身`、可完整重放且通过事务校验的提交补丁，以及当前实时 MVU 中存活身体至少两个稳定身份字段（姓名/种族/职业）与人物卡一致。任一可见字段冲突、生命值不为正或只匹配一个字段都会拒绝。
- 首次成功恢复后会立即重建并长期保存该确认记录的可信指纹；后续刷新、更新及历史快照不可见时可直接走可信恢复，不再反复依赖兜底。
- 恢复回执会写明本次使用了“完整确认链＋当前身体双字段一致性”，便于区分普通同步与旧聊天修复。

## v0.9.3：旧聊天身份自愈与防再次清空

- 修复旧聊天的历史楼层没有向扩展公开 `stat_data` 快照时，严格复核误清空已确认当前身体、界面退回“当前变量未提供姓名”的问题。
- 恢复时会同时核对完整人物卡、独立的精确口令 `确认换身`、AI 的完整提交补丁、插件保存的可信记录指纹，以及当前 MVU 中仍存活且匹配的种族/职业/姓名；任一明确冲突都不会恢复。
- 当前实时状态现在直接通过酒馆/MVU 公共接口参与恢复，不再要求它必须出现在历史消息对象里。
- 已确认记录的可信指纹改为独立长期保存；即使滚动备份被后续世界书备份挤出，也不会失去恢复依据。旧迁移备份和已经执行过的跨世金钱回执也可提供原插件写入的可信凭据。
- 自动恢复成功后会显示恢复回执并继续向 AI 注入完整人物档案。删除确认楼层、修改确认消息、当前身体已死亡或身份字段冲突时仍会安全撤销，不会错误复活旧身份。

## v0.9.2：浮动入口自愈与背景缺失提示

- 修复酒馆热更新后残留旧按钮时提前退出的问题；现有不可见按钮也会被重新赋予固定定位和最高显示层级。
- 浮动球改到正文右侧中部，避开底部发送栏，紫色“历”字更容易识别。
- “当前身体人生背景”板块现在始终显示。旧人物卡没有背景时会明确说明原因，不再让该板块看起来像是完全不存在。

## v0.9.1：浮动球显示修复

- 浮动球关键样式现在由扩展脚本同步注入，不再依赖浏览器是否及时刷新 `style.css` 缓存。
- 提高浮动球和弹窗层级，并使用强制可见规则，避免被正文面板、底栏或其他扩展覆盖。
- 页面加载后，正文右下角会显示紫色“历”字浮动球；点击即可打开同一个历代人生管理器面板。

面向死亡换身及历代重要经历管理的 SillyTavern 前端扩展。保存与展示已确认的当前身体档案，按世代整理人生摘要，并通过明确按钮把待归档草稿写入同一本既有世界书。默认使用严格主档案注入：每轮同时发送插件完整人物档案与正文实时变量，并按明确的字段优先级合并；也可选择智能、完整、精简或关闭。

## v0.9.0：正文浮动入口与当前身体人生背景

- 正文页面右下角新增“历”浮动球，点击即可打开同一套历代人生面板；关闭后面板回到扩展设置原位，不建立第二份数据。
- 新人物卡支持独立“人生背景”板块，覆盖原主从出生、家庭、成长、教育或谋生、重要关系与转折、能力及身份来源，一直写到接管时年龄。
- 插件会把人生背景单独解析并显示为“当前身体人生背景”，并在每次生成前明确写入 AI 上下文。它属于当前身体的记忆与经历来源，不会被误当成历代前世人格或技能。
- 旧人物卡仍可正常使用；没有独立背景板块时只显示兼容提示，不会编造背景或破坏既有档案。

## v0.8.0：正文动态与 AI 注入同源

- 每次生成前重新读取最新 `stat_data`，把伤势、状态效果、卫生、穿着、形态、改造、地点和数值组成“当前有效动态覆盖”，与完整接管档案一起实际写入 AI 上下文。
- MVU 楼层快照暂时延迟时，可从最新助手正文的安全 JSONPatch 提前补入普通动态；姓名、换身阶段和整份载体替换仍必须通过原有持久化确认链，不能靠正文补丁偷换身份。
- 当前身体页会显示“已写入 AI 上下文”、正文来源楼层和待落盘变化数量；设置页仍可展开查看本轮实际发送的完整提示。
- 接管时原始人物卡不被破坏。最新动态作为覆盖层执行，明确治愈、移除或更换后的状态不会被旧人物卡重新复活。

## 安装与更新

在 SillyTavern 的扩展管理中安装：

```text
https://github.com/jiangshuyu132-cloud/SillyTavern-LegacyLifeManager.git
```

分支或标签留空，使用 `main`。已经从本仓库安装的用户，在扩展管理中检查更新、更新本扩展后刷新页面，确认版本为 0.11.1。保留自动更新设置。此仓库是前端扩展，不是酒馆助手脚本导入 JSON。

## 0.7.1 的变化

- 修复旧 MVU 楼层未保存完整提交快照时，刷新后把已经确认的当前身体清空并错误退回开局人物的问题。
- 插件只会在人物卡、精确确认口令和原始楼层指纹均未改变，且当前实时身体仍与档案一致时，使用自己保存的可信备份恢复。
- 删除确认楼层、修改确认记录或实时身体不匹配时仍然撤销，不会让已失效的旧身体复活。
- 已使用真实聊天 JSONL 回放验证：可恢复第2世“芙莉莲”和第1世“菜月昴”经历索引。

## 0.7.0 的变化

- 新增并默认启用“严格主档案”：正常剧情的每一轮都发送完整已确认人物卡，不再只在换身后的第一轮发送。
- 明确双来源合并：插件详细人物设定为主档案；正文 `stat_data` 的物品、装备、资产、任务、关系、新闻、数值和其它实时变化仍全部有效。
- 状态效果不再让简短状态条覆盖完整设定：变量负责存在、层数、持续时间与即时变化，插件负责完整症状、身体表现和长期影响；明确治愈、移除及新增状态仍以实时变量为准。
- 设置页可以展开查看“本轮实际发送给 AI 的插件资料”，方便确认模型每轮拿到了什么。

## 0.6.0 的变化

- `主角.金钱` 成为死亡换身中唯一跨世保留的资源。确认换身时按真实确认链读取旧身体最后余额；若模型用新身体初始现金覆盖，插件只校正一次，并保留确认换身后已经发生的收支变化。之后的正常收入和消费不会被刷新回滚。
- 等待换身、等待确认和确认首轮只向 AI 注入一段轻量金钱连续性规则，不恢复旧人格、技能、属性、背包、装备、房产或身份权利。
- 当前身体页面显示“跨世金钱”。点击灰色头像即可导入或更换图片；图片会居中裁切、压缩并按聊天中的具体世代保存，也可随时移除。头像只用于插件界面，不发送给 AI、不参与正文或生图。

## 0.5.2 的变化

- 修复旧聊天 MVU schema 保存种族、地点和生命值，却静默丢弃 `换身状态`、`载体档案`和`历代记忆摘要`后，插件无法识别新身份的问题。
- 恢复时必须同时核对：旧身体 HP 为 0、正文完整候选卡与 MVU 候选摘要的姓名/种族一致、玩家独立发送 `确认换身`、AI 完整提交换身补丁、新身体 HP 大于 0，并且种族/职业/地点至少一项与人物卡匹配。仅有候选卡或文字声称仍不会被误导入。
- 同一条警告在 1.5 秒内只显示一次，避免连点或重复事件产生双重提示。

## 0.5.1 的变化

- 精确口令：玩家原始消息仅去除首尾空白后必须等于 `确认换身`。解释性长句、引用或角色对白不能代替。
- 采用载体之前核对真实消息 MVU 快照：死亡成立、阶段为等待确认、当前候选一致，提交后世代增加一、当前姓名一致、旧索引保留并追加一项、候选与死亡状态清理。
- 单独的确认消息或正文 JSONPatch 文本不能证明 MVU 已执行；候选修改或废弃后不能采用旧卡。
- 人物卡按钮仅同步已经有完整提交证据的档案，不能直接接管候选或绕过口令。同一换身记录去重。
- 当前人格、认知边界字段映射补全；技能以实时 `主角.技能` 为先。当前身体注入以持久消息状态为依据，避免历史补丁重复覆盖和待归档草稿复活。
- 等待换身、候选、确认首轮及场外讨论暂停当前身体注入。下一次普通玩家输入后恢复。
- 归档流程加入单实例锁、确认链及草稿校验、精确聊天/消息检查。新建和同文去重分支都需要后端回读，之后在同一个精确消息更新中清理状态和草稿；接口不支持时保留草稿。
- 同名异文、同世异人停止，不按更长摘要覆盖冲突记录；冲突记录不注入为事实。新 UID 同时避开对象键与内部 uid。
- 成功清理归档草稿不会使已确认载体消失。首次升级保留独立旧账本备份，并纳入插件备份导出。

## 使用流程

1. 使用匹配的死亡换身世界书和预设，由模型维护真实 MVU 状态。只有正文真正死亡后才进入候选流程。
2. 生成候选时，将完整人物卡及起止边界存入 `主角.换身状态.待确认人物卡`。候选不覆盖当前载体。
3. 玩家亲自发送独立消息 `确认换身`，等待主 API 回复及 MVU 写回。插件核对完整提交链后同步当前身体。
4. 在“历代人生”的设置中选定本聊天使用的既有归档世界书。点击“把待归档前世写入世界书”并核对目标，插件实际保存及回读后清理对应草稿。
5. 正文中的玩家台词、选择和主动行动仍由玩家输入。当前人格只影响已授权行为的理解与执行，不否决或偷换行动。跨世索引只代表经历，不恢复旧人格、语言、技能和属性。

人物卡采用 `【当前载体人物设定开始】` / `【当前载体人物设定结束】` 边界。字段独立输出，例如 `<b>世代编号：</b>第2世<br>`、`<b>姓名：</b>姓名<br>`。人物卡按钮和“扫描并修复”只同步已经核实的记录，不为缺失的状态编造一次确认。

上一笔草稿仍为“待写入世界书”时，应先完成该笔归档，再提交下一次换身，避免覆盖单字符串草稿。

## 数据与旧聊天兼容

保留原 MVU 路径，不新增 MVU 事务字段：

- `stat_data.主角.载体档案`：当前身份、人格、认知及背景。
- `stat_data.主角.换身状态`：阶段、当前世代编号、当前身体死亡已确认、当前身体死亡信息、待确认人物卡、待归档人生词条、归档写入状态。
- `stat_data.主角.本世经历草稿`：由模型维护的本世经历。
- `stat_data.历代记忆摘要`：根层短索引。

阶段使用“当前身体生效 / 等待换身 / 等待确认”；归档状态使用“无待处理 / 待写入世界书 / 已写入世界书”。世代为数字，死亡标记为布尔值，候选和详细草稿为字符串。

详细词条沿用 `[历代记忆档案]第N世·姓名`。草稿提供独立 `词条名称: 第N世·姓名` 行，以及重要人物、关键地点、重大事件、别名单行供关键词提取。本地摘要、MVU 短索引与已保存世界书是不同存储层；显示摘要不证明世界书已经保存。

首次升级在 `chatMetadata.legacy_life_manager.legacyMigrationBackup` 保存旧插件账本。没有完整状态快照的旧载体可能暂停注入，备份可随插件备份导出；不会为了通过核对重置真实 MVU 或删除世界书。内部兼容标记延续首个迁移补丁，避免重复迁移。

导入初始化世界书不能自动补全旧聊天 schema。缺字段、仅保存候选摘要或缺历史快照时，需依据真实存档修复，不应把空模板覆盖旧世代、索引或待写草稿。旧聊天的常规资料仍可从既有主角字段和匹配的初始主角卡只读补全。

聊天消息删除、编辑或切换会重新核对派生账本；已经写入世界书的记录不会自动删除。自行修改历史后应核对三层记录。

## 接口与边界

使用 `SillyTavern.getContext()`。MVU 优先读取酒馆助手公开变量接口，其次 MVU 自身接口与消息快照。归档清理要求按精确消息地址更新，不能用仅支持 latest 的接口在异步保存后盲目清理。

插件不替玩家生成候选、发送口令或把人物卡写成 MVU 当前人物；模型提供草稿，插件按钮执行世界书保存。完整聊天原文只进入主动导出的备份，不整体注入模型；不读取 API 密钥。

保存时具有单实例互斥、上下文检查与后端回读，不能宣称多个客户端同时编辑时具备数据库级事务锁。实际模型表现、预设助手和自定义 MVU schema 仍依赖使用环境。
